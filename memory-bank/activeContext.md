# Active Context

## Current State

- The site uses Svelte 3 and the existing SvelteKit/Vite/Tailwind toolchain.
- Page content, project data, site settings, images, CV, sitemap, and SEO metadata are local.
- The canonical project registry contains five projects in the preserved display order.
- The projects panel shares the same structured blocks as each dedicated project route.
- The only new runtime request is same-origin `POST /api/contact` when the form is submitted.
- The contact endpoint needs server-only Resend and sender/recipient configuration in Cloudflare Pages.

## Important Patterns

- Routes live under `src/routes`; reusable block components live under `src/lib/blocks`.
- Current structured content is in `src/lib/content`; settings are in `src/lib/config/site.js`.
- `src/lib/generated/images.js` is generated by `npm run images` and keeps migrated Twill LQIPs while unchanged image bytes remain stable.
- Panel, theme, and navigation state use `src/store.js`; API settings/cache stores have been removed.
- Preserve current JavaScript, Svelte 3 conventions, layout classes, dark mode, lazy loading, and history behavior.
- Rich text HTML is trusted migrated CMS content and is rendered inside block components only.

## Verification Notes

- `npm run build` succeeds with the current SvelteKit version.
- No automated lint or test scripts are configured.
- `adapter-auto` reports that the local build environment is not a recognized production target; it includes Cloudflare Pages support when built in that environment.
- The backend `.test` host could not be reached from this sandbox. The migration archive records that API URL patterns are derived from the installed Twill/Glide code and are unverified over HTTP.
