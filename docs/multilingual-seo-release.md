# Multilingual SEO release notes

## SEO and sitemap behavior

- English pages use the existing unprefixed routes. German pages use `/de` routes.
- Canonical URLs and `og:url` use the current page path on `https://www.armin.ba`. The production homepage remains available on that domain; no staging host is used as canonical.
- Titles and descriptions come from the active locale's Twill settings for home, about, contact, and projects. Project details use the translated project title, description, and image.
- Page and project language alternates are emitted only after the other locale's API endpoint returns a successful response. Project detail availability follows Task 01's shared-slug and per-locale publication contract. Missing or unpublished detail requests keep their API 404 and do not render SEO canonicals.
- The language switcher preserves project-detail URLs only when that slug appears in the selected locale's published project list; unavailable translations are disabled. A stale project-panel request is discarded if the URL or locale changes while it is loading.
- `/sitemap.xml` is generated by the frontend from the locale-aware page endpoints and published project lists. It includes `/contact` in both locales because that route is localized in the frontend. Project detail URLs appear only for slugs returned by that locale's published project list. The sitemap uses canonical URLs and reciprocal `xhtml:link` entries for available locale pairs.
- If a sitemap API source is temporarily unreachable or returns an unexpected error, the endpoint returns `503` without caching a partial sitemap. Locale-specific `404` responses are treated as genuine unavailability and omitted.
- `static/robots.txt` already points to `https://www.armin.ba/sitemap.xml` and needs no change.
- Server-delivered `<html lang>` remains set by `src/hooks.server.js` from the request path before hydration.

## Backend sitemap follow-up

The backend currently schedules `generate:sitemap` daily. `GenerateSitemap.php` crawls `https://www.armin.ba` and writes a separate `public/sitemap.xml` on the backend host. The frontend no longer proxies that generated file; the canonical public sitemap is now the frontend route on `www.armin.ba`. The backend API robots file does not advertise its copy, but the backend host may still serve it directly.

The separate Codex follow-up **“Retire the backend sitemap generator”** (task `01a15689-ac00-7971-8fdc-2982482b2ebe`) is to remove the daily sitemap schedule and stop publishing the backend-host copy (including an already generated file if it is tracked or deployed). It must confirm the backend robots response does not advertise a sitemap, add focused coverage or operational verification for the retired command/route, document the deployment sequence, and keep all changes on a separately reviewable backend branch. Coordinate its deployment before or with the frontend SEO rollout so the frontend remains the single authoritative public sitemap generator. No backend repository files were changed for this frontend task.
